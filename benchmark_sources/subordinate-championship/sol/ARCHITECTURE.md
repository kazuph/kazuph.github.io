# 設計と受け入れ契約

## 決定事項
TASK.md の全11項目を対象とする。Workers の公式ローカル環境だけで実行し、8783を使用する。デプロイ・ログイン・外部API・別AIへの委任・pushは行わない。元のチェックアウトは main のまま、`git wt --nocd --basedir .worktree quiz-local` で作成した配下で実装し、納品時に main に fast-forward する。

## 構成
Worker が静的画面と部屋作成・参加のHTTP APIを提供する。1部屋につき1つの SQLite Durable Object にプレイヤー、得点、問題番号、回答権、期限を保存する。WebSocketで同じ状態を全員に配信する。Durable Objectのイベント処理を排他実行し、最初に受信した有効な早押しだけを確定する。永続化後に配信する。ブラウザに正解・他人の復帰トークンを渡さない。

参加時の推測困難なトークンをタブのsessionStorageに保存し、再読込・通信断では同じトークンで再接続する。接続が切れてもプレイヤーを削除しない。複数接続は同じプレイヤーとして扱い、二重加点しない。新規参加はロビーのみ。ホストだけが2〜4人で開始できる。

期限はサーバーの絶対時刻。回答は10秒以内、出題全体は20秒以内で、短い方を優先する。Durable Object alarm と各入力時の期限確認を併用し、操作がなくても進行する。ブラウザはサーバー時刻との差から残り時間を描画するが、判定には関与しない。

## 明示した解釈
- 回答時間切れは不正解（-5点）として、その問題の早押しを禁止する。
- 正解した時点でもその問題を終了する。全員失格・20秒経過でも終了する。
- 正解表示のための未指定の待ち秒数は追加しない。直前の問題と正解を次の出題画面に残し、同じ配信で次の問題に自動進行する。最終問題の正解は順位画面に残す。
- 同点は同順位。10問・各4択は内蔵データを使用し、出題順は固定する。
- ロビーの切断プレイヤーも定員に含む。タブを閉じた場合のsessionStorage消失・別端末への本人移行は要件外。

## 選ばなかった構成
D1/KVのみでは、早押しの排他制御と接続管理が別途必要になる。部屋単位の状態にDOのSQLiteを使えば整合性と永続化を一箇所に置ける。外部配信サービスは課題で禁止。ポーリングは即時の回答権共有に不向きなためWebSocketを選んだ。React等のフレームワークは画面数が少なく不要なので、依存の少ないDOM APIとCSSで構成する。

## 検証の対応
純粋な状態遷移関数で得点・失格・期限境界・順位を検査する。実際のwrangler devに対するブラウザE2Eで4人同時プレイ・競合・権限・満室・リロード・オフライン復帰・実時間10秒/20秒・全10問を検査する。PCとスマホのロビー・出題中・回答中・順位のPNG、要素の収まり・重なりの数値検査を保存する。未検証はRESULT.mdで未達とする。

公式仕様: [DO WebSocket](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)、[DO state](https://developers.cloudflare.com/durable-objects/api/state/)。
