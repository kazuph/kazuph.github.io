# アーキテクチャ

## 採用した構成

```
ブラウザ (vanilla JS SPA)
  │  WebSocket  /api/room/<コード>/ws
  ▼
Cloudflare Worker (src/index.ts)  ── 静的アセット (public/) の配信
  │  env.ROOMS.idFromName(コード)
  ▼
Durable Object "Room" (src/room.ts)  × 1部屋 = 1インスタンス
  ├─ 部屋の状態 (プレイヤー・得点・フェーズ) をメモリ + DOストレージで管理
  ├─ 早押し判定 / 正誤判定 / 加点減点
  └─ storage.setAlarm() で制限時間 (20秒/10秒/reveal表示) をサーバー駆動
```

## 選んだ理由

### Durable Objects (SQLite-backed) + WebSocket

- **「サーバーが最初に受け取った1人だけが回答権を得る」を確実にしたいため。**
  Durable Object は1インスタンスが1部屋に対応し、イベント(メッセージ)を
  シングルスレッドで順次処理します。`onBuzz()` は「回答権が空いているかの判定」と
  「占有」の間に `await` を挟まない同期的な check-and-set になっており、
  4人が同時に押しても**処理順に1人だけ**が回答権を得ます。
  分散した状態を持つ構成 (例: KV や D1 を共有状態にする) では、この「先着1人」を
  条件付き書き込みや楽観ロックで自前実装する必要があり、競合の心配が残ります。
- WebSocket は DO の標準機能で、全員の画面への push 配信 (state スナップショット) に使います。
  追加のミドルウェア・外部サービス不要で完結します。
- 状態 (プレイヤー・点数) は DO 内に持つので、WebSocket が切れても再接続時に復元できます。

### タイマーはサーバー側 (`storage.setAlarm`)

- 「出題から20秒」「回答10秒」「reveal表示からの自動進行」はすべてサーバー時刻の deadline で管理します。
  クライアントは deadline の epoch ms を受け取り、時計ずれを補正 (`now` フィールド) して
  残り時間のゲージを描くだけ。判定はしないので、端末の時計やタブのスロットルに左右されません。
- 遷移は DO の `alarm()` で行うので、ブラウザの申告を一切信用しません。

### 再接続 (項目10)

- 初回参加時にサーバーが `token` (UUID) を発行し、ブラウザは `sessionStorage` に保存。
  再読み込み・回線切断時は同じトークンで再接続し、**同じプレイヤーID・点数のまま**復帰します。
  クライアントは指数バックオフで自動再接続します。

### フロントエンドをバニラ JS + 静的アセットにした理由

- ゲームロジックはほぼサーバー側にあり、クライアントは状態の表示と送信だけです。
  バンドラ・フレームワークを導入するメリットより、構成がシンプルになる方が価値が高いと判断しました。
- Wrangler の `[assets]` 機能で `public/` をそのまま配信します。

## 選ばなかった案

| 案 | 選ばなかった理由 |
| --- | --- |
| **D1 / KV を部屋の状態に使う** | 「先着1人」の原子的な判定を SQL や KV の条件付き書き込みで実現するのは難しく、競合時に素朴にならない。レイテンシも DO 直の方が有利。永続DBの必要性もない (部屋はゲーム中だけ生きる)。 |
| **SSE + ポーリング** | クライアント→サーバーの早押し送信が別 HTTP になり、push との整合 (表示の同時性) を保ちにくい。双方向は WebSocket が素直。 |
| **Workers だけ (DO なし) + 複数インスタンスの合流** | Worker は同一リージョンでも複数アイソレートで動くため、早押しの全順序を1箇所で決められない。DO の採用理由そのもの。 |
| **外部のリアルタイム配信サービス (Pusher 等)** | 決定事項「外部サービス不使用・Cloudflare 内で完結」により不可。 |
| **クラウドデプロイ / リモート DO** | ローカル `wrangler dev` のみで完結。ログイン不要。 |

## ゲームルールの実装上の解釈

- **正解が出た時点でその問題は終了**し、正解を全員に表示して次の問題へ進みます
  (仕様の8に「全員が押せなくなるか20秒経過」で進むとある中で、正解者がいたケースの扱いを
  一般的な早押しクイズに合わせて解釈。誰も正解できなければ誤答ロック全員か20秒で終了)。
- 回答10秒のタイムアウトは失点なしで回答権をはく奪し、押せる人で早押しを再開します
  (仕様は不負け・不勝ちと読めるため)。この場合もそのプレイヤーはその問題ではもう押せません。
- 5人目はロビー中でもゲーム中でも参加できず、「部屋が満員です（定員4人）」と表示されます。
  ゲーム進行中の新規参加 (再接続以外) は受け付けません。
- ホストがロビーで退出した場合、接続中の先頭プレイヤーにホストを譲渡します
  (ゲーム開始できなくなるのを防ぐため)。
