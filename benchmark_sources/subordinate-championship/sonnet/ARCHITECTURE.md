# アーキテクチャ

## 結論

**Cloudflare Workers + Durable Object（1部屋＝1インスタンス）+ WebSocket（Hibernation API）+ Workers Static Assets**。ほかの Cloudflare 製品（D1・KV・Queues 等）は使わない。

```
ブラウザ ──HTTP──▶ Worker ──静的ファイル──▶ public/（index.html, app.js, style.css）
   │                 │ POST /api/rooms … 部屋コードを払い出す
   └──WebSocket /ws/ABCD──▶ Worker ─▶ Durable Object「Room」(idFromName("ABCD"))
                                         ├─ 状態（プレイヤー・点数・出題・締切）を storage に保存
                                         ├─ 時間切れは alarm（次の締切に1本だけ予約）
                                         └─ 変化のたびに全員へ最新状態（スナップショット）を配信
```

## 選んだ理由

| 要件 | 選択 | 理由 |
|---|---|---|
| 「サーバーが最初に受け取った1人だけ」 | Durable Object | DO は同じ部屋のメッセージを必ず1つずつ直列に処理する。同時に押されても処理順が1つに決まり、ロックや排他制御のコードが要らない。早押し判定の正しさを**プラットフォームの保証**に乗せられる |
| 部屋ごとの状態 | DO のメモリ ＋ `storage.put` | 部屋の寿命は短く小さい（4人・10問）。D1 のような外部DBを挟むと往復が増え、「同時押し」の公平さも落ちる。毎回 storage に書くので、DO が休止・再起動しても状態は残る |
| 4人へのリアルタイム配信 | WebSocket（Hibernation API） | 外部のリアルタイム配信サービスは使えない。DO が直接 WebSocket を受け、アイドル時は休止できる |
| 10秒・20秒・正解表示の進行 | DO の `alarm()` | `setTimeout` は休止すると消える。alarm は休止しても発火する。**次の締切1つだけ**を予約し、発火時に `tick(now)` が期限切れをまとめて処理する（冪等） |
| 画面の配信 | Workers Static Assets（`run_worker_first` は `/api/*` と `/ws/*` のみ） | ビルド工程なしの素の HTML/JS/CSS。ローカルでも `wrangler dev` だけで動く |
| 部屋コード | Worker が乱数4文字（紛らわしい文字を除く32種）を作り、DO の `/claim` で「先に取った方が勝ち」 | 衝突しても DO が 409 を返すので再抽選できる。存在しない部屋に入ろうとすると「見つかりません」と理由を出せる |

## 判定はすべてサーバー側

- 画面は「押した」「この選択肢を選んだ」という**意図だけ**を送る。誰が最初か・正誤・点数・タイムアウトは `src/game.ts` が決める。
- 出題中のスナップショットに**正解の位置を含めない**（正解表示のときだけ `correctIndex` を送る）。ほかの人の復帰トークンも載せない。どちらも結合テストで確認。
- 時刻はすべてサーバー時刻。画面の残り時間は「サーバー時刻の締切 − (ブラウザ時刻 + サーバーとの差)」で計算するので、端末の時計がずれていても全員で同じ値になる。

## 進行ルールの決めごと（仕様の曖昧な点を、こう解釈した）

- **回答中は20秒で打ち切らない**: 「出題から20秒で正解表示」は「誰も回答していない待ち時間」に適用する。19秒に押した人が1秒しか答えられないのは不公平なので、回答権を得た人の10秒は最後まで待つ（最長30秒）。回答が不正解で終わったとき、すでに20秒を過ぎていたら残りの人を待たず正解表示へ進む。
- **10秒選ばなかったら不正解扱い**（-5点、その問題では押せない）。
- **回答できるのは回答権のある本人だけ**。それ以外の選択は拒否され点数は変わらない。
- **全員が押せなくなる = その部屋の全プレイヤーが不正解でロックされた**。接続が切れているだけの人は、戻って押せる可能性があるので数える。
- **ゲーム開始後の新規参加は拒否**。復帰は、入室時に受け取って localStorage に保存したトークンで行う。
- **ロビーでの切断**は15秒の猶予後に席を空ける（ホストなら次の人が引き継ぐ）。ゲーム中の切断は席も点数も保つ。

## 復帰（再読み込み・回線断）

- 入室時にサーバーが「公開ID」（他人に見せてよい）と「トークン」（本人だけの秘密）を発行。ブラウザは `localStorage` に部屋コード・トークンを保存。
- ページを開き直す／WebSocket が切れると、保存済みのトークンで `hello` を送り直して同じプレイヤーに戻る。切れたときは 0.4秒→最大3秒の間隔で自動再試行し、「再接続しています…」を表示する。
- 同じトークンの古い接続が残っていたら、サーバーが閉じて新しい接続に置き換える（再読み込み直後の二重接続対策）。

## 選ばなかった案

- **D1 / KV に状態を置き、Worker 側で判定**: 同時に来た2つの押下が両方「まだ誰も押していない」を読める（読み書きの競合）。排他のために条件付き更新やリトライが必要になり、DO の直列処理より複雑で遅い。
- **全部屋を1つの DO に集約**: 部屋同士が互いの待ち時間に影響し、スケールしない。部屋ごとに DO を分けるのが Cloudflare の想定どおり。
- **ポーリング（HTTP の定期取得）**: 早押しの遅延と無駄な通信が増え、「同時押し」の公平さも落ちる。
- **クライアントが判定し、サーバーは中継だけ（P2P 的）**: 不正申告を防げない。決定済み事項（判定はサーバー）に反する。
- **フロントのビルド（React / Vite プラグイン）**: 画面は小さく、ビルドなしの素の JS のほうが起動・テストが単純。Cloudflare 公式 Vite プラグインは不要と判断した。
- **ロックのための `blockConcurrencyWhile` やミューテックス**: DO はメッセージ処理が直列なので不要。

## テストの考え方（3層）

1. **単体**（`tests/unit`）: 進行ロジックは純粋関数なので、時刻を引数で渡して全ルール（定員・開始条件・同時押し・得点・ロック・各タイムアウト・復帰）を一瞬で検証。
2. **結合**（`tests/integration`）: 本物の workerd を一時起動し、WebSocket で人間の代わりに4人分を同時操作。DO・alarm・永続化・Hibernation 経路を含めて確かめる。
3. **ブラウザE2E**（`tests/e2e`）: 実際の画面で、押す・選ぶ・再読み込み・回線断・満員表示・スマホ幅の横スクロールなしを確かめ、スクリーンショットを保存。

## 既知の限界（未検証・未対応）

- Durable Object の**強制退避（メモリ破棄）直後の復元**を再現するテストは書いていない。状態は毎回 storage に保存し、constructor で読み戻す作りにしてある。
- 部屋は終了後も storage に残る（ローカル開発のため掃除はしていない）。
- 同じブラウザの2つのタブで同じ部屋に入ると、後から開いたタブが優先され、先のタブは切断される（別のプレイヤーとして遊びたい場合は別ブラウザ／プライベートウィンドウを使う）。
