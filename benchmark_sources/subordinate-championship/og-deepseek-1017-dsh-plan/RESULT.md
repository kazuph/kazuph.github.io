補足:

- **同時押し**: `buzzer.spec.ts` が4人ぶんのクリックを `Promise.all` で同時に送り、サーバーが最初の1人だけを回答者にすること（4択が有効な画面がちょうど1つ）を確認している。単体テストでは4人の全24通りの処理順を試し、どの順でも最初の1人だけが勝つことを確認している。
- **再読み込み復帰**: `localStorage` に残した `token` で再接続し、同じ席・同じ点数に戻ることを実ブラウザで確認している。
- **4人同時プレイ**: `full-game.spec.ts` で4つの独立したブラウザ（PC幅3・スマホ幅1）が同じ部屋で10問を最後まで遊ぶ。

## 4. 未達・代用・制限

- **結合テストの専用実装は未実施**: Cloudflare の `@cloudflare/vitest-pool-workers` を使った独立の結合テストは用意していない。かわりに Playwright の E2E が実際の `wrangler dev`（Worker + Durable Object + WebSocket + Alarm）に対して操作するため、結合の確認は E2E で代用している（上の表に「代用」と記載）。
- **デプロイは未実施**: 課題の指定どおり、デプロイも Cloudflare アカウントへのログインもしていない。確認はすべてローカル（`wrangler dev`、`http://localhost:8787`）で行った。
- **スクリーンショットは `.gitignore` 済み**: 課題の指定どおり `.artifacts/` はコミットしていない。再生成は `npm run test:e2e -- full-game.spec.ts`。
- **Windows は対象外**: 課題の指定どおり Linux / macOS 前提。
