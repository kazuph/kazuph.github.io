# RESULT

課題の「遊び方」11項目と、テスト・UIについて、確かめた方法と達成状況をまとめる。
判定は次の3種類。

- **達成**: テストまたはスクリーンショットで実際に確かめた。
- **代用**: 似た挙動で確かめた（内容を明記）。
- **未達**: 確かめていない、または実装していない。

実行コマンドは `npm test`（型検査 → 単体 → ブラウザ）。ブラウザテストは
`wrangler dev` を Playwright が起動して実行し、時間は短縮していない。

- 単体テスト: `tests/unit/game.test.ts`（22件）
- ブラウザテスト: `tests/e2e/*.spec.ts`（7件）
  1. `lobby.spec.ts`「4人まで参加でき、5人目は満員で断られる（ロビーのスクリーンショット付き）」
  2. `lobby.spec.ts`「存在しない部屋コードでは入室できない」
  3. `lobby.spec.ts`「1人では開始できず、2人そろうとホストだけが開始できる」
  4. `play.spec.ts`「4人が同時に押しても回答権は1人だけ／不正解／再読み込み復帰／時間同期」
  5. `reconnect.spec.ts`「回線が一時的に切れても自動で再接続し、同じプレイヤーとして復帰する」
  6. `timeout.spec.ts`「誰も押さないと実時間20秒で正解表示、押して放置すると10秒で-5点」
  7. `fullgame.spec.ts`「10問を最後まで遊ぶと、4つの画面に同じ最終順位が出る」

## 4. 補足（未確認・代用）

- **回線切断の方法は代用**: `reconnect.spec.ts` では、ブラウザの `offline` イベントを
  発火させてクライアントから接続を閉じてから `context.setOffline(true)` で5秒間
  実際にオフラインにし、`online` イベントで再接続している。「サーバーが切断を検知して
  他画面に表示 → 復帰で消える」ところまで確かめている。実機の Wi-Fi 断は試していない。
- **ブラウザは Chromium のみ**: Playwright の chromium で検証。Firefox / Safari
  （WebKit）での動作は未確認。
- **コピー機能**: 部屋コードの「コピー」ボタンは実装済みだが自動テストは未実施。
- **負荷・低速回線**: 極端に遅い回線や高負荷時の挙動は未確認。
- **本番デプロイ**: 方針どおり未実施（`wrangler dev` のローカル実行のみ）。
- **Windows**: 対象外のため未確認。
