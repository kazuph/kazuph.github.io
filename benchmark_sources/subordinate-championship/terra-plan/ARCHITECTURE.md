# 構成と判断

Workers が部屋コードを検証し、コードに対応する Durable Object に作成・参加・WebSocket を転送します。1部屋に1つの SQLite 版 Durable Object を割り当て、参加者、問題順、得点、状態と期限を保存します。判定と採点はサーバー側の純粋なゲーム規則で行います。WebSocket Hibernation API で接続を保持し、状態全体を参加者ごとに配信します。回答中は正解と他人のトークンを送りません。最も近い期限を Alarm に設定し、通信がなくても進行します。メッセージ受信時も期限を先に処理します。

ブラウザは参加時の識別情報を localStorage に保存し、切断時に再接続します。得点と席は Durable Object に残ります。画面の残り時間は配信されたサーバー時刻との差を使います。静的ファイルは Workers Static Assets で配信し、ビルド用フレームワークを必要としません。

KV は同時押しの順序を一箇所で決める用途に適さず、D1 単独では接続と期限の進行も別途必要です。Durable Object は部屋単位の順序付け、保存、WebSocket と Alarm をまとめて扱えるため選びました。外部の配信サービスは使いません。
