# 構成

ブラウザ → Workers → 部屋コードごとの Durable Object → Durable Object Storage。静的ファイルは Workers Assets から配信する。Cloudflare の `wrangler dev --local` でローカル実行し、アカウントや外部配信サービスは使わない。

部屋ごとの Durable Object が参加者、点数、問題番号、回答権、締切を保持する。処理を直列化し、最初に受け付けた早押しだけに回答権を渡す。正解はサーバー内の問題データだけに置き、正解発表までブラウザへ送らない。問題締切と回答締切はサーバーの時刻で判断し、Durable Object の alarm でも進行する。各ブラウザは定期的に部屋の最新状態を取得し、サーバー時刻との差を使って残り時間を表示する。プレイヤー ID をブラウザの localStorage に保存し、再読み込み・一時切断後は同じ ID で状態を取得する。

WebSocket は双方向の即時通知に向くが、この規模では短い定期取得とサーバー側の締切で構成を簡潔にできるため選ばなかった。KV は同時更新の整合性をこの用途に使いにくく、D1 単独では同じ部屋の早押しと締切をまとめる仕組みが別途必要になるため選ばなかった。保存データは Wrangler のローカルストレージに残る。ブラウザの保存データを消すと同じプレイヤーとして復帰できない。
