# ARCHITECTURE — 4人オンライン早押しクイズ

Cloudflare Workers のランタイムだけで動く、最大4人の早押しクイズです。ローカルでは `wrangler dev`（`http://localhost:8786`）で動かし、デプロイはしません。

## 全体の構成

```
 ブラウザ ×4（public/ の HTML・CSS・JS）
   │  ① POST /api/rooms             … 部屋を作る（名前）
   │  ② POST /api/rooms/:code/join  … 参加する（名前）→ playerId と token を受け取る
   │  ③ GET  /api/rooms/:code/ws    … WebSocket（playerId + token で本人確認）
   ▼
 Worker（src/index.ts）……… 静的ファイル配信（Workers Static Assets）と受付だけ。状態を持たない
   │  idFromName(部屋コード) で、部屋ごとに1つの Durable Object へ転送
   ▼
 Durable Object「Room」（src/room.ts）………… 1部屋 = 1インスタンス
   ├ ゲームのルール（src/game.ts の純粋関数）を、届いた順に1つずつ適用
   ├ 状態を Durable Object のストレージ（SQLite 版）へ毎回保存
   ├ 全員の WebSocket を Hibernation API で保持し、状態が変わるたびに全員へ配信
   └ 次の締め切り（3秒前振り・20秒・10秒・5秒）に Alarm を1つだけ合わせる
```

| 使った機能 | 役割 |
|---|---|
| Workers | API の受付、`public/` の配信（Static Assets、`/api/*` だけ Worker を先に通す） |
| Durable Objects（SQLite ストレージ） | 1部屋の状態・ルール判定・点数・順番の唯一の持ち主 |
| WebSocket Hibernation API | 4人への即時配信。待ち時間中はインスタンスを休ませられる |
| Durable Object Alarms | 20秒・10秒・正解発表5秒などの時間切れをサーバー側で確実に進める |

外部サービス・有料機能・外部のリアルタイム配信は使っていません。Cloudflare アカウントへのログインも不要です（`wrangler dev` はローカルの workerd と Miniflare で完結）。

## なぜこの組み合わせか

**早押しの「最初の1人」を一意に決めるため。** Durable Object は1つのインスタンスがイベントを1件ずつ処理するので、4人の「押した」が同時に届いても処理順は必ず一列に並びます。`buzz()` は「出題中なら回答権を渡して状態を『回答中』にする」だけなので、2件目以降は状態が既に『回答中』で `not_open` として弾かれます。ロックや分散トランザクションが要りません。

**全員の画面をそろえるため。** 状態はサーバーの1か所だけにあり、変わるたびに同じ JSON を全員へ送ります。残り時間は「締め切りの時刻（サーバー時計）」で配り、各画面は ping/pong で測ったサーバー時計とのずれを足して描きます。端末ごとの時計のずれや、受信の遅れがあっても同じ残り秒数が出ます。

**時間切れを確実に進めるため。** `setTimeout` はインスタンスが休止・破棄されると消えますが、Alarm はストレージに保存され、休止中でも起こしてくれます。締め切りは常に1つ（`nextDeadline()`）なので Alarm も1つで足ります。メッセージ処理の前にも `tick()` で期限切れを先に進めるので、Alarm が少し遅れても「20秒を過ぎた早押し」は受け付けません。

**再読み込み・回線断から戻れるようにするため。** 参加時にサーバーが `playerId` と推測できない `token` を発行し、ブラウザは `sessionStorage`（タブごと・再読み込みで残る）に保存します。再接続時に同じ組を出せば同じ席・同じ点数に戻ります。切断してもプレイヤーは消さず「切断中」と表示するだけです。画面は WebSocket が閉じると 0.4 秒から最大5秒の間隔で自動的につなぎ直します。

**ルールを単体で確かめられるようにするため。** ルールは `src/game.ts` に、時刻と乱数を引数で受け取る純粋関数として分けました。Durable Object は「今の時刻で関数を呼んで、保存して、配る」だけです。

## 選ばなかった案

| 案 | 選ばなかった理由 |
|---|---|
| KV に部屋の状態を置く | 結果整合で書き込みの順番が保証されず、同時押しの先着判定ができない。即時の配信手段もない |
| D1（SQLite）に状態を置き、HTTP ポーリング | 早押しのたびにトランザクションが必要で、配信はポーリングになり遅延とずれが大きい。部屋単位の直列化は Durable Object の方が自然 |
| 全部屋を1つの Durable Object で扱う | 全部屋の処理が1本に詰まり、無関係な部屋の早押しが互いを待たせる。部屋ごとに分ければ負荷も障害も部屋の中で閉じる |
| Durable Object 内の `setTimeout` で時間管理 | 休止・破棄で消える。Alarm なら保存される |
| 標準の `ws.accept()`（休止しない WebSocket） | 動くが、問題の待ち時間中も課金対象の実行時間が続く。Hibernation API はコード量も同程度 |
| Server-Sent Events + POST | 押す・選ぶの送信が別経路になり、順序とつながり直しの扱いが二重になる |
| Cloudflare Realtime（旧 Calls）など | 音声・映像向けで、クイズの状態同期には大きすぎる。課題の「有料の外部サービスを使わない」にも合わない |
| PartyKit・Socket.IO などのライブラリ | 中身は同じ Durable Object + WebSocket。依存を増やさなくても数百行で書ける |
| React などの画面フレームワーク + Vite プラグイン | 画面は6種類で、状態はサーバーから丸ごと届く。ビルド工程なしの素の JS にして `wrangler dev` だけで動くようにした |
| ブラウザ側で正誤判定・タイマー | 申告を信用しない決まりに反する。正解の番号は正解発表までブラウザへ送っていない |

## 状態とルールの流れ

```
lobby ──(ホストが開始・2〜4人)──▶ countdown(3秒) ──▶ question(早押し受付・出題から20秒)
                                                       │  最初の1人が押す
                                                       ▼
                                                    answering(10秒)
                                     正解 +10 ──────────┤
                                                       ├─ 不正解 -5 / 10秒切れ -5 → その人は押せない
                                                       │     ├ まだ押せる人がいて20秒以内 → question に戻る
                                                       │     └ 全員押せない or 20秒を過ぎた → reveal
                                                       ▼
 reveal(正解を全員に表示・5秒) ──▶ 次の question … 10問目の後 ──▶ finished(最終順位) ──(ホスト)──▶ lobby
```

## 仕様の解釈（課題文に書かれていない点）

- **20秒と10秒が重なったとき**: 早押しの受付は出題から20秒で締め切ります。19秒目に押した人にも10秒の回答時間を与え、その回答が終わった時点で（正解・不正解・時間切れのいずれでも）正解発表に進みます。20秒を過ぎてから新しく押すことはできません。
- **回答権を得たのに10秒以内に選ばなかった**: 不正解と同じ扱い（-5点、その問題では押せない）。
- **切断中のプレイヤー**: 席と点数は残り、「全員が押せなくなる」の判定にも含めます（戻ってきて押せるため）。誰も押さなければ20秒で次へ進みます。
- **正解発表の表示時間** 5秒、**開始前のカウントダウン** 3秒。
- **ゲーム中の新規参加** は断ります（「ゲームが始まっているため参加できません」）。再接続は可能です。
- **同じ名前** の参加は断ります（画面で見分けられないため）。名前は1〜12文字。
- **同点** は同じ順位にします。
- **再戦**: 最終順位の後、ホストが「もう一度遊ぶ」を押すと同じメンバーで点数0のロビーに戻ります。
- 部屋の自動削除はしていません（ローカル開発専用のため）。

## セキュリティ上の境界

- 早押しの順番・正誤・点数・締め切りはすべて Durable Object が決めます。ブラウザから届くのは「開始」「押す」「選択肢の番号」だけで、回答権のない人の回答・範囲外の番号・期限後の回答は拒否します。
- 正解の番号は `reveal` になるまで配信データに含めません（`toPublic()`）。
- `token` は配信データに含めず、WebSocket 接続時の本人確認にだけ使います。
- 名前は画面に出すときに必ずエスケープします。
