# アーキテクチャ

## 結論

**1部屋 = 1つの Durable Object** とし、その中で状態・判定・点数・早押しの順番をすべて決める。通信は **WebSocket（Hibernation API）**、時間切れは **DO の alarm**、画面は **Workers Assets の素の HTML/JS** で配る。外部の有料サービスや外部のリアルタイム配信は使わない。

## 全体の構造

```
ブラウザ（4人ぶん）
  │  fetch: POST /api/rooms, POST /api/rooms/:code/join, GET .../check
  │  WebSocket: /api/rooms/:code/ws?playerId=...
  ▼
Worker（src/index.ts）── /api/* 以外は Workers Assets（public/）を返す
  │  部屋コード → idFromName(code) で DO を一意に決める
  ▼
Durable Object「QuizRoom」（src/room.ts・部屋ごとに1個）
  ├─ state を ctx.storage に保存（再起動・休止しても消えない）
  ├─ 判定は src/game.ts の純粋関数に委ねる（advance / buzz / answer / startGame ...）
  ├─ 接続ごとに playerId を attachment に持たせる（休止しても誰かが分かる）
  └─ alarm：回答期限（10秒）・問題期限（20秒）・正解表示の終わり（5秒）で起きて advance する
```

## 処理の流れ（早押しの例）

1. 4人がほぼ同時に `{type:"buzz"}` を送る。
2. DO は WebSocket のメッセージを1件ずつ処理する（同じ DO 内では並行に走らない）。
3. 最初に処理された `buzz` だけが `buzzerId` を得る。後の `buzz` は「ほかの人が先に押しました」で断る。
4. 状態を保存し、alarm を回答期限に張り直し、全員に画面情報を配る。

「サーバーが最初に受け取った1人だけ」は、この1件ずつの処理で保証される。結合テスト（4人同時に押す操作を5回）と E2E（4つのブラウザから同時に押す）で確かめている。

## 選んだ理由と、選ばなかった案

| 項目 | 選んだもの | 選ばなかった案と理由 |
|---|---|---|
| 状態の置き場所 | Durable Object の storage（1部屋1個） | **D1（SQL データベース）**：同時押しの順番を「先に書いた人が勝ち」にするには、トランザクションで競合を解く必要がある。部屋1つの状態は DO 内で直列に処理するほうが単純で、正しさを保ちやすい。<br>**KV**：結果整合で、同時押しの順番を保証できない。 |
| リアルタイム通信 | WebSocket（Hibernation API） | **ポーリング（定期的な問い合わせ）**：早押しは数百ミリ秒の差で勝敗が決まるので、遅延と負荷の面で不利。<br>**Server-Sent Events**：一方向で、押す操作を別の経路で送る必要がある。 |
| 時間切れ | DO の alarm | **ブラウザのタイマー**：ブラウザの申告を信用しない方針に反する。<br>**setTimeout（DO 内）**：DO が休止すると消えるため、再接続後に期限が狂う。alarm は休止を越えて起きる。 |
| 画面の配信 | Workers Assets（素の HTML/JS） | **Vite＋フレームワーク**：ビルド工程が増える。4画面・数百行の規模では得るものが少ない。<br>**Pages（別プロジェクト）**：デプロイ前提の構成になり、ローカル専用の方針と合わない。 |
| 再接続の識別 | 端末に保存した `playerId`（UUID） | **Cookie・ログイン**：認証基盤が必要になり、ローカル限定の課題の範囲を超える。<br>**接続ごとに新しい ID**：再読み込みで点数を失うので不可。 |
| 同じ人の二重接続 | 新しい接続を受けるとき、古い接続を閉じる | 二つとも開かせると、同じ人が2回押せてしまう。 |
| 問題の出し方 | アプリ内蔵の16問から毎回10問をランダムに選ぶ | 外部 API から取る案は、決定事項「外部APIから取らない」に反する。 |

## 状態の遷移

```
lobby ──start（ホスト・2〜4人）──▶ question ──押せる人がいる間──▶ question
                                      │ 正解 / 全員不正解 / 時間切れ
                                      ▼
                                   reveal（正解表示 5秒）──▶ 次の question
                                                              │ 10問終わった
                                                              ▼
                                                           finished（最終順位）
```

- `question`：押す → 回答権を得る（回答期限は「押した時刻＋10秒」と「問題の期限（20秒）」の早いほう）。
- 回答期限を過ぎた、または不正解：-5点、その問題では押せない。残りの人がいれば `question` のまま続く。
- 誰も残らない、または正解：`reveal`。

## 画面に渡す情報（秘密の扱い）

- 問題中は正解の番号を画面に渡さない（`viewFor` で `reveal` のときだけ渡す）。ブラウザのコードを読んでも先に分からない。テストで JSON に `"answer"` が含まれないことを確かめている。
- 時刻は「サーバーの時計」で渡し、画面は差分でカウントダウンを描く。端末の時計がずれても残り時間は合う。

## 既知の限界

- 認証がない。`playerId` を知っていれば、その人として接続できる（ローカル限定のため許容）。
- 回線が切れている間に回答期限が来ると、その人は-5点になる（サーバーの時計で判定するため）。
- DO の状態はローカルの `.wrangler/state` に保存される。`.wrangler/` を消すと部屋は消える。
