# アーキテクチャ

## 採用した構成

Cloudflare Workers + Durable Objects（SQLite 版）+ WebSocket Hibernation API + Alarm + Workers Static Assets。
（この構成は上司の実装計画 `PLAN.md` で決まっていたもの。以下は、その理由と、実装で補った点。）

```
ブラウザ ── HTTP ─────────► Worker（src/worker.ts） ──► 部屋コードで Durable Object を引く
   │                           │ 静的ファイル（public/）は Worker を通さず Assets が返す
   └── WebSocket ────────────► Room（src/room.ts, 1部屋 = 1インスタンス）
                                 ├─ game.ts（規則。純粋関数）
                                 ├─ storage に state を保存
                                 └─ Alarm = いちばん近い締め切り1つ
```

### なぜこの構成か

| 要件 | 選んだ仕組み | 理由 |
|---|---|---|
| 「サーバーが最初に受け取った1人」だけ回答権 | 1部屋 = 1 Durable Object | DO は1インスタンスが単一スレッドで、メッセージを1つずつ処理する。ロックや CAS が要らず、同時押しの順番が一意に決まる |
| 全員の画面を同期 | WebSocket + 状態の全量配信 | 差分更新より単純で、再接続・再読み込みのときも同じ処理で復帰できる |
| 時間切れ（20秒・10秒・3秒） | DO の Alarm | 誰もメッセージを送らなくても時間は進む。1部屋につき最も近い締め切り1つだけ予約すれば足りる |
| 再読み込み・回線断から復帰 | state を DO の storage に保存、token で本人確認 | DO が Hibernation で眠ってもメモリが消えても、storage から読み直して続けられる |
| 外部サービス無し | Workers 内で完結 | 有料の外部配信サービスは不要 |

- **Hibernation API**: `ctx.acceptWebSocket(ws, [playerId])` で接続を受け、接続ごとに playerId をタグで持つ。接続の一覧は `ctx.getWebSockets()` から取るので、DO が眠って起きても失われない。
- **状態は1キーに全量を保存**: 部屋の状態は小さい（4人・10問）ので、`ctx.storage.put("game", state)` でまとめて書く。メッセージを処理するたびに `tick`（時刻を進める）→ 処理 → 保存 → Alarm 再予約 → 全員へ配信、の順。
- **規則は `game.ts` の純粋関数**: 時刻 `now` を引数で受け取り副作用を持たないので、「24通りの押す順番」「20秒・10秒の境目」を実時間を使わずに単体テストできる。DO は入出力だけを担当する。
- **時刻はサーバーの時計だけ**: メッセージを処理するときも Alarm のときも、まず `game.tick(state, now)` で過ぎた締め切りをまとめて進める。ブラウザは `serverNow` との差を `performance.now()` で数えるので、端末の時計がずれても残り時間は全員で同じになる（E2E で端末の時計を1時間進めて確認）。
- **正解は出題中に送らない**: `toPublic()` が state を作るとき、正解の番号は `reveal` のときだけ入れる。ほかの人の token も含めない。

### 実装で補った点（PLAN.md に細部の指定が無かったところ）

- `GET /api/rooms/:code/me?token=…`: 保存していた token がまだ有効かを返す。再接続の前に呼び、部屋が消えた・token が違うときだけ入口に戻す（回線が無いだけのときは、そのまま再試行を続ける）。
- 同じ token の新しい接続が来たら古い接続を close code 4000 で閉じる。閉じられた側は再接続しない（二つの画面が奪い合いにならないように）。
- 部屋コードの重複は `create` が 409 を返したら Worker が別のコードで最大5回やり直す。
- 切断中の人の判定は、`ctx.getWebSockets()` に開いた接続があるかどうか。接続が閉じたとき（`webSocketClose` / `webSocketError`）に全員へ再配信する。

## 選ばなかった案

| 案 | 選ばなかった理由 |
|---|---|
| D1 / KV に状態を置いて Worker だけで処理 | 同時押しの「最初の1人」を決めるのに排他制御が要り、結果整合の KV では決められない。リアルタイム配信の手段も別に要る |
| ポーリング（HTTP を一定間隔で叩く） | 早押しの遅延が大きく、順番の公平さを保証しにくい。配信の無駄も多い |
| 1つの DO に全部屋 | 全部屋のメッセージが1つのスレッドに並んでしまい、部屋が増えると遅くなる。1部屋 = 1 DO ならスケールも隔離も自然 |
| WebSocket を Hibernation 無しで持つ（`ws.accept()`） | DO が常にメモリに居座る。Hibernation なら待ち時間は課金・メモリを使わず、起きたときは storage から復元できる |
| フロントにフレームワーク / ビルド | 画面は4つで状態の描画だけ。ビルド無しの素の JS で足りて、依存と起動手順が減る |
| 外部のリアルタイムサービス | 課題の決定事項で禁止（Cloudflare の機能の中で完結させる） |

## 既知の制約（意図的に扱っていないもの）

- 終了した部屋のデータは削除しない（ローカル開発用。`.wrangler/state` を消せばリセットされる）。
- 名前の重複は許している（IDで区別する）。
- 回線が切れた人も席は埋まったままで、ゲーム中に退出して席を空ける機能は無い。
