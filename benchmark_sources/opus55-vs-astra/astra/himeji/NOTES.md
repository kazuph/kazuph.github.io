# 姫路城 — 白鷺のジオラマ

## 開き方

`index.html` をブラウザで開きます。ローカルサーバーやビルドは不要です。Three.js 0.180.0 と OrbitControls だけを CDN から読み込むため、初回表示にはインターネット接続と WebGL が必要です。

- 左ドラッグ：城の周囲を回転
- ホイール／ピンチ：拡大・縮小
- 右ドラッグ：注視位置を移動
- 「南西から」：初期の展示アングルへ戻る
- 「縄張りを見る」：天守群の配置が見える俯瞰へ移動
- 「自動回転」：ゆっくり回転する展示モード
- 「建物名」：大天守・西小天守・乾小天守・東小天守を表示

## 姫路城として意識した特徴

**一棟の五重塔ではなく、連立式の天守群。** 大天守を南東、西小天守を南西、乾小天守を北西、東小天守を北東に置き、四辺の渡櫓で囲んだ構成にしました。最初の視点を南西に置き、西側の二つの小天守から大天守へと高くなる輪郭を見せています。奥の東小天守は回転や俯瞰で確認できます。

**五重の大天守と三重の小天守。** 大天守は下部二重を幅広くし、上部三重を絞りました。実物の大天守は外観五重・内部六階ですが、この作品は外観模型であり、内部の床・柱・階段は作っていません。

**白漆喰と灰色の瓦屋根。** 外壁だけでなく、破風の縁、窓格子、軒裏の垂木も白系に統一。完全な白ではなく、温かみのある漆喰色と明るい縁材を使い分けています。瓦の列は細い円柱を曲面に沿って並べた立体形状で、斜めからも屋根の細かな凹凸が残ります。

**千鳥破風と唐破風の重なり。** 大きな三角形の破風、左右一対の小さな破風、中央が膨らむ曲線の唐破風を屋根面に重ねました。単純な屋根の積層から離れ、姫路城らしい複雑な白い輪郭を出すための中心的な意匠です。棟端には鯱を抽象化した小さな立体を置いています。

**防御施設も模型の一部に。** 下階の張り出した石落とし、窓の格子、土塀の狭間、門の開口、曲がった登城路、石段を造形。石垣は下部が広く、上部が狭い台形断面とし、個々の石の色・幅・表面の起伏を変えています。

## ジオラマとしての工夫

- 深緑の角を丸めた台座に、細い真鍮色の縁と銘板を付け、建築模型として自立する展示物にしました。
- 天守台・上段・下段の高さを分け、石垣と城の垂直方向の量感を強調しています。
- 土の庭、砂利、桜の花びら、松、常緑樹、春の桜を配置。中央の城を隠さず、外周の低い植栽で大きさの比較ができるようにしています。
- 小さな人物を置き、壁と天守のスケールを示しています。
- 暖色の斜光、青みの補助光、柔らかな環境光を組み合わせました。背景は静かなグレーベージュで、白壁・瓦・緑・桜の色を引き立てます。
- 屋根の瓦列、格子、木々、砂利などの反復形状は InstancedMesh にまとめています。細部を消さず、描画命令を共有する方式です。
- 乱数は固定シード `1609`。再読込しても同じ石積み・樹形になります。

## 再現範囲とデフォルメ

これは測量図に基づく厳密な復元モデルではなく、天守群を中心とした建築ジオラマです。連立式の配置と代表的な意匠を保ちつつ、各建物の寸法、屋根の勾配、石垣の段差、曲輪、登城路、西の丸の位置関係を展示台に収まるよう圧縮しています。実際の城域全体・堀・都市・全ての門櫓を網羅するものではありません。桜の配置も展示構成上の演出です。小天守の火灯窓や実物の鯱の細かな彫刻までは再現していません。

## 制作ルール

HTML 内のコードが、屋根・壁・石・樹木・台座をすべて構築します。既存3Dモデル、外部テクスチャ画像、写真素材は使用していません。銘板の文字だけは、端末のフォントを Canvas に描いて作ったローカル生成の文字テクスチャです。外部取得するのは Three.js のプログラムモジュールだけです。他モデルの成果物の参照や、別AI・子エージェントへの委任は行っていません。

## 参照した建築資料

- [兵庫県立歴史博物館「姫路城」](https://rekihaku.pref.hyogo.lg.jp/castle/himeji/)：各方角から見た天守群、破風、最上重の壁面、石落とし、瓦と漆喰。
- [姫路城公式サイト「城の楽しみ方」](https://www.city.himeji.lg.jp/castle/0000007738.html)：三小天守と破風の説明。
- [文化庁「国指定文化財等データベース：姫路城 八棟」](https://kunishitei.bunka.go.jp/heritage/detail/102/2264)：五重六階の大天守と三小天守の構成。

写真は参照情報としてのみ使用し、作品内には取り込んでいません。

## 検証

`tests/e2e/diorama.spec.ts` は、実際の Google Chrome を Playwright Test から起動して `file://` で開きます。マウスドラッグ・ホイール・表示ボタンを操作し、カメラ位置／距離の変化を数値で確認します。初期画角では各メッシュの境界を画面へ投影して、模型が画面内に収まることも検証します。

`verification.json` に実行時の描画数、投影範囲、操作結果、画面寸法、読み込みエラーを記録。`screenshot.png` は完成HTMLの1600×1100ピクセルのブラウザスクリーンショット、`mobile-check.png` は390×844ピクセルの補助確認画像です。スクリーンショットは画像生成AIによる代替画像ではありません。

再実行（既存の Playwright と Google Chrome を利用）：

```sh
node_modules/.bin/playwright test tests/e2e/diorama.spec.ts --workers=1 --reporter=line --output=test-results
```
