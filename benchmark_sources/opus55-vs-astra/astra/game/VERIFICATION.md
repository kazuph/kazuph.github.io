# 検証記録 — 読んだら負け。

## 依頼と成果物

> X（旧Twitter）で一番バズるゲームを作ってください。

エントリポイントは `index.html`。バズを狙う設計理由と遊び方は `CONCEPT.md`。ビルド不要の静的HTML/CSS/JavaScriptで、ローカルファイルでもHTTP配信でも遊べます。ブラウザでのレビュー用に `http://127.0.0.1:18765/` を開いています。

## 検証方法

既存の Playwright Test 1.59.1 とインストール済みGoogle Chromeを使用。ブラウザ追加インストール、モック、時計の早送り、ゲーム状態の書き換え、回答用の内部APIは使用していません。ブラウザに表示された文字・計算済みの色・ルールを読み取り、実際のクリック・タップ・数字キーで回答します。

再実行（ローカルサーバー起動中）：

```sh
node node_modules/@playwright/test/cli.js test
```

アプリ本体にはPlaywrightやNode.jsは不要です。

## 既に確認したこと

- `node --check game.js` 成功。
- PCで練習の正誤、カウントダウン中の入力無効、12問の正解、5問目と10問目のルール反転、誤答時の残り時間3.0秒減少。
- 12正解・1誤答から、正答率92%、最長連続12問、反転2回を表示。
- 共有URLに結果と日付を含む投稿文が入り、他人から開けないlocalhostは含まれない。
- 実クリップボードへのコピーが共有文と一致。再読込後の自己ベスト12問を確認。
- 再挑戦は0点から開始し、同じ日付の第1問が一致。
- 無操作での時間切れは実測29,943ms（カウントダウン終了を検知してから計測）。0正解、履歴0件、終了後の入力で加点されない。
- PC・スマホの実画面をPNGとして保存し、開いて確認。表示の判定はスクリーンショットだけに頼らず、DOMの幅・要素座標・はみ出し・文字クリップを測定。

## 修正と回帰確認

初回画面確認で、練習の正解ボタンにマウスを重ねると背景色がホバー用に戻り、暗い文字が読みにくくなる問題を修正。選択済みの正誤表示をホバーが上書きしないようにし、背景色と文字色の回帰テストを追加しました。

初回のスマホテストは、終了直前の誤答のあとも次問へ進むと仮定したテストコードが失敗。ゲームは正しく結果画面へ移っていました。「次問へ進む、または時間切れで結果へ進む」という実際の仕様を検査し、結果の点数と回答件数の一致を維持するようテストを修正しました。初回の結果は `evidence/first-run-results.json` に保持しています。
